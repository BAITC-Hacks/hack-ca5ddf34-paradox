# EKT AI — frontend

Адаптивный интерфейс консультанта: чат, карточки товаров, серверное сравнение аналогов, загрузка спецификаций, проверка предложения и корзина. Дизайн: светлый фон, красные акценты EKT, компактная навигация.

## Сборка и просмотр

Для разработки с backend на другом порту (Node.js 20.19+):

```sh
npm run dev
```

Откройте `http://127.0.0.1:5173`. Команда сначала собирает HTML, затем запускает frontend-сервер. По умолчанию `/api/*`, `/cart` и `/cart/*` проксируются на `http://127.0.0.1:3000`, где слушает backend. Backend запускается отдельно. В корневом `.env` установите `PUBLIC_APP_URL=http://127.0.0.1:5173`, чтобы Origin-проверка подтверждения корзины и ссылка на демо-корзину совпадали с frontend-origin. Используйте один и тот же хост (`127.0.0.1`) в браузере и настройках.

Переменная `BACKEND_URL` меняет адрес backend proxy. Переменные `HOST` и `PORT` меняют адрес frontend-сервера. Для запуска и сборки установка npm-зависимостей не нужна; `npm ci` нужен для DOM-тестов. После правки исходников выполните `npm run build` и обновите страницу.

Proxy сохраняет cookies, заголовок CSRF, статусы ответов и multipart-тело загрузок. Он не переписывает `cartUrl`, cookies или цены. Для локального запуска backend должен выдавать cookie для текущего хоста и `cartUrl: "/cart"` либо URL frontend-origin. Используйте один и тот же хост в адресной строке (не переключайтесь между `localhost` и `127.0.0.1`). Если backend возвращает абсолютный URL своего отдельного origin, фронт показывает его как получен от сервера.

Это сервер разработки: он раздаёт только готовый HTML и публичные frontend-ресурсы. `.env`, исходники сервера и тесты по HTTP недоступны. Сам сервер не читает `.env`.

Готовый **`index.html` содержит стили, иконки и JavaScript внутри одного файла**. Его можно скачать отдельно и открыть двойным кликом: оформление работает без соседних файлов и внешних CDN. При локальном открытии показывается режим просмотра: интерфейс доступен для оценки, отправка сообщений, загрузка файлов и корзина отключены до подключения backend на том же origin.

После изменения исходников пересоберите этот файл (Node.js 20+, установка зависимостей для сборки не нужна):

```sh
npm run build
```

Редактируйте разметку в `src/index.template.html`, оформление в `styles.css`, логику в `api.js`, `view-model.js` и `app.js`. Корневой `index.html` генерируется автоматически. `node build.mjs --check` проверяет, что готовый файл соответствует исходникам; `node build.mjs --output /path/to/preview.html` создаёт отдельную копию для просмотра.

## Размещение

Бэкенд должен раздавать готовый `index.html` на **том же origin**, что и `/api/*`. Не перехватывайте API-маршруты обработчиком статических файлов. Корневой URL фронта — `/`; файл можно разместить в каталоге статики существующего бэка. Если на сервере включён CSP, разрешите встроенные стили и скрипты с помощью хешей или серверного nonce. При каждом изменении исходников сначала выполняйте сборку.

Откройте URL этого сервера в браузере. `python -m http.server` без backend API показывает интерфейс, но не создаёт сессию. Открытие `index.html` через `file://` показывает режим «Просмотр интерфейса» с сохранённым стартовым экраном. Демо-ответов и локальной корзины в этой версии нет.

Не добавляйте Basic Auth каталога, ключи модели или платёжные данные в frontend. Все доступы к каталогу принадлежат серверу. Cookies отправляются через `credentials: "include"`; клиент не отправляет session ID и историю диалога.

## API

| Действие | Запрос | Использование ответа |
|---|---|---|
| Открытие интерфейса | `GET /api/session` | CSRF только в памяти; корзина из `cart` |
| Отправка сообщения | `POST /api/chat`, JSON `{ "message": "..." }` | `reply`, карточки, аналоги, `proposal`, предупреждения |
| Открытие корзины | `GET /api/cart` | Актуальные `items`, `totalMinor`, `cartUrl` |
| Явное подтверждение | `POST /api/cart/confirm`, JSON `{ "proposalId": "..." }`, заголовок `X-CSRF-Token` | Корзина из ответа и прямая `cart.cartUrl` |
| Загрузка файла | `POST /api/attachments`, multipart, единственное поле `file` | Позиции добавляются в редактируемое поле чата; отправка вручную |

### Предложение и корзина

1. Кнопка «В корзину» на карточке открывает выбор количества и города.
2. Кратность берётся из `facts.orderMultiple`. Текущий backend принимает только целое количество, поэтому товары с дробной кратностью не дают подготовить предложение.
3. «Проверить наличие и цену» отправляет обычное сообщение в `/api/chat` для подготовки предложения. Это не изменяет корзину.
4. Полученное `proposal` отображается со всеми девятью полями: `id`, `productId`, `productName`, `productArticle`, `quantity`, `city`, `unitPrice`, `totalAmount`, `expiresAt`.
5. Только явный клик **«Да, добавить в корзину»** отправляет `/api/cart/confirm`. Текст «да» в чате никогда сам не вызывает этот маршрут.
6. При 409, 404 или истечении срока старое предложение блокируется. Для продолжения нужен новый `proposal` от сервера.
7. При сетевой неопределённости или HTTP 5xx во время подтверждения (включая timeout proxy) предложение блокируется; пользователь должен проверить корзину. Сервер мог успеть добавить товар до ошибки. Автоматического повтора нет. Повторный клик во время запроса также блокируется.
8. Корзина обновляется только из `/api/session`, `/api/cart` или успешного `/api/cart/confirm`. Никаких локальных вычитаний остатков или расчётов итогов.

### Вложения

PDF, DOCX, XLSX и JPEG, не более 10 МБ. После извлечения артикулы, названия, количество и единицы дописываются в composer, сохраняя уже введённый текст. `uncertainties` и неопределённые строки видны пользователю. Загрузка не отправляет запрос в чат и не меняет корзину.

### Форматы данных и неопределённости

Контракт задаёт верхние поля `price`, `stock`, `facts`, `source`, но не полностью определяет внутреннюю структуру. Адаптеры в `view-model.js` изолируют этот участок:

- Цена: число/числовая строка отображается без выдуманной валюты; объекты `{amount, currency}` или `{amountMinor, currency}` поддерживаются. Только явное `amountMinor` делится на 100. Неизвестный формат показывается как «Не указана» и блокирует подтверждение предложения.
- `cart.totalMinor` имеет определённую контрактом размерность: делится на 100; валюта в контракте не задана и не подставляется.
- Остатки: число или явные `quantity`/`available`/`total`; поддержаны `byCity`/`stores` с явным городом. Неизвестный остаток не считается нулём; остатки складов не суммируются на клиенте.
- Факты: объект или массив `{name|label|key, value}`. `orderMultiple` распознаётся явно, без извлечения из свободного текста.
- `source` отображается как текст/ссылка, без заявления о проверенности; ссылки с опасными протоколами или встроенными credentials не принимаются.
- `cartUrl` поддерживает абсолютный HTTP(S) URL и безопасный относительный путь на том же origin, включая `/cart`; значение сервера не переписывается.
- Сравнение показывает серверные `{field, requested, offered, verdict}`. `match` → «Совпадает», `different` → «Отличается», `unknown` → «Неизвестно».
- Общие суммы `proposal.totalAmount` всегда отображаются из ответа, не пересчитываются из цены и количества.

Адаптеры сверены с JSON backend в `docs/API.md`. Корзина демонстрационная и хранится в памяти backend; это не корзина ekt.kz.

## Проверки

Node.js 20+:

```sh
npm install
npm run build
npm test
npm run check
```

`npm run test:contract` выполняет тесты API и адаптеров без установки зависимостей. Тест сборки создаёт отдельный HTML в пустой временной папке и проверяет встроенные стили, порядок и синтаксис скриптов, отсутствие внешних ресурсов оформления и актуальность результата. DOM-тесты используют `linkedom` и реальные файлы UI с подставленными ответами сервера: проверяют отсутствие изменения корзины без клика, точное тело подтверждения, 409, загрузку и проверку кратности. Это не проверка реального сервера и не визуальный тест в браузере.

Тесты proxy запускают локальный HTTP backend с тестовыми ответами: проверяют маршрутизацию API и корзины, cookies, CSRF, multipart, статусы ошибок и отсутствие доступа к непубличным файлам. Пользовательский сценарий в DOM-тесте: поиск → карточки и сравнение аналогов → просмотр точных полей предложения → явное подтверждение → обновление корзины и ссылка.

## Файлы

- `index.html`: готовый автономный HTML для просмотра и размещения.
- `src/index.template.html`, `styles.css`: исходная разметка и адаптация.
- `build.mjs`: сборка HTML без дополнительных зависимостей.
- `dev-server.mjs`: локальный frontend-сервер с proxy на backend; не является частью backend.
- `api.js`: same-origin HTTP, cookies, CSRF, таймауты и безопасные ошибки.
- `view-model.js`: преобразование данных для отображения, ссылки и проверка предложений.
- `app.js`: события интерфейса, карточки, proposal, вложения, корзина.
- `tests/`: тесты контракта, адаптеров и поведения UI.

Сервер должен самостоятельно проверять сессию, CSRF, принадлежность предложения пользователю, срок действия, idempotency, цену, городской остаток, кратность и загружаемые файлы. Клиентские ограничения не заменяют эти проверки.
